# Database Integrity and Business Logic Automated Testing Suite

An enterprise-grade, Behavior-Driven Development (BDD) End-to-End (E2E) Black-Box integration testing pipeline engineered to validate database constraints, data integrity, and backend business logic (SQL Server Triggers). 

This project utilizes **Python Behave** for human-readable testing specifications, **SQLAlchemy** for secure database connections, and **Pandas DataFrames** for robust data validation and assertions.

---

## 🏗️ Architecture & Framework Flow

The framework bridges human-centric business specifications with live database integration tests using a three-tier architecture:

* **Behavioral Layer:** Gherkin `.feature` files define expected data workflows and business logic requirements in plain English.
* **Infrastructure Layer:** `SQLAlchemy` safely manages database connections, handles session pooling, and wraps raw transactional `INSERT/UPDATE` executions safely.
* **Data/Validation Layer:** `Pandas` executes queries over connection tunnels and pulls records directly into structured DataFrames to run automated data integrity assertions.

This functions as a **Black-Box Test**: the automation suite inserts data into the system and verifies the final output, ensuring that the database's internal processing, triggers, and constraints work correctly without needing to alter the underlying database engine code.

---

## 📊 Database Schema Blueprint & Constraints

The testing suite targets a relational architecture featuring the following entities and constraints:

* **Core Entities:** `departments`, `employees`, `salaries`, `customers`, `suppliers`, `products`.
* **Transactional Ledger:** `sales` and `purchases` tables tied tightly to core master data via strict Foreign Key dependencies.
* **Business Logic Automation:** A `discounts` table managed by a native database trigger (`trg_calc_discount`). The trigger intercepts transactions, processes cross-table calculations against the `sales` entity, and programmatically maintains real-time markdown values.

### Core Constraints & Triggers Addressed:
* **Identity Columns:** Primary keys like `sale_id`, `employee_id`, and `discount_id` use `IDENTITY(1,1)` and are automatically generated by SQL Server.
* **Foreign Keys:** Transactions in the `sales` table strictly require valid, existing matching rows within the `products`, `customers`, and `employees` tables.
* **Trigger Mechanics:** ```sql
  CREATE TRIGGER trg_calc_discount
  ON discounts
  AFTER INSERT, UPDATE
  AS
  BEGIN
      UPDATE d
      SET d.discount_amount = (s.sale_price * d.discount_percent / 100)
      FROM discounts d
      INNER JOIN sales s ON d.sale_id = s.sale_id
      INNER JOIN inserted i ON d.discount_id = i.discount_id;
  END;
